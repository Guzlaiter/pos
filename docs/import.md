# Импорт старой базы

## Что импортируется

Сервис импорта переносит три типа данных:

1. **Категории** — название, тип, порядок сортировки.
2. **Товары и услуги** — название, артикул, тип, категория, цена,
   себестоимость, единица, остаток, складской учёт, активность.
3. **Способы оплаты** — название, тип, признак «влияет на кассу», порядок,
   активность.

Продажи, смены и пользователи из старой базы не импортируются. Это осознанное
ограничение: структура чеков и смен сильно отличается, а перенос без
сопоставления мог бы исказить статистику. Пользователи создаются заново.

## Поддерживаемые файлы

- SQLite: `*.db`, `*.sqlite`, `*.sqlite3`.
- CSV/текст: `*.csv`, `*.txt`.

База открывается **только на чтение**, поэтому старый файл не изменяется.
Кодировка CSV определяется автоматически (`UTF-8`, `UTF-8 с BOM`, `CP1251`,
`UTF-16`), разделитель — `;`, `,`, табуляция или `|`.

## Порядок работы

1. Откройте **Импорт данных** (право `import_data`).
2. Выберите файл. Приложение покажет список таблиц/листов и количество строк.
3. Выберите таблицу-источник.
4. Укажите, что импортировать: категории, товары или способы оплаты.
   Тип можно определить автоматически по названию таблицы.
5. Проверьте сопоставление колонок. Обязательное поле — **Название**.
6. При необходимости измените настройки:
   - **Цены в рублях** или **уже в копейках**;
   - **обновлять существующие** позиции;
   - **импортировать остатки**.
7. Посмотрите предварительный просмотр: первые строки с преобразованными
   значениями.
8. Запустите импорт и проверьте отчёт: создано, обновлено, пропущено,
   обновлено остатков, ошибки.

Перед записью автоматически создаётся резервная копия с тегом
`before-import`. Каждый импорт фиксируется в `import_jobs` (файл, таблица, тип,
сопоставление, результат, пользователь, дата).

## Сопоставление колонок

Приложение предлагает соответствия по русским и английским названиям
колонок. Например:

| Поле | Возможные колонки |
| --- | --- |
| Название | `Наименование`, `Название`, `name`, `title`, `товар`, `услуга` |
| Артикул | `Артикул`, `SKU`, `Код`, `Штрихкод`, `barcode` |
| Тип | `Тип`, `Вид`, `type`, `kind` |
| Категория | `Категория`, `Группа`, `category`, `group` |
| Цена | `Цена`, `Стоимость`, `Розница`, `price`, `sale_price` |
| Себестоимость | `Себестоимость`, `Закупка`, `cost`, `purchase_price` |
| Остаток | `Остаток`, `Количество`, `qty`, `stock` |
| Единица | `Единица`, `Ед.`, `unit` |

Сопоставление можно изменить вручную. Значения-константы (например, «всегда
товар» или «услуга») задаются отдельно от колонок.

## Правила импорта

### Цены

- Режим «в рублях»: `150.50` → `15050` копеек.
- Режим «в копейках»: `15050` → `15050` копеек.
- Поддерживаются пробелы, запятые, символы `₽`, `руб.`.
- Некорректная цена превращается в `0`; строка не теряется.

### Товары и услуги

- Если указан артикул, позиция ищется по нему (без учёта регистра).
- Иначе — по названию и типу.
- При `update_existing = True` найденная позиция обновляется.
- При `update_existing = False` найденная позиция пропускается.
- Новая категория создаётся автоматически, если её ещё нет.
- Услуга никогда не получает складской учёт.
- Остаток импортируется только для товаров со складским учётом и только если
  включена опция «импортировать остатки».
- Остаток задаётся как **целевое количество**: создаётся движение `import` на
  разницу между текущим и импортируемым остатком. Повторный импорт без
  изменения количества не создаёт лишних движений.
- Отрицательный остаток приводится к нулю.

### Способы оплаты

- Поиск по названию без учёта регистра.
- При совпадении обновляются тип, касса, порядок и активность (если включено
  обновление).
- Тип распознаётся по словам: `наличные/cash`, `qr`, `перевод/transfer`,
  `терминал/карта`, остальное — `other`.
- Признак «влияет на кассу» можно задать колонкой или константой.

### Ошибки

Ошибки по отдельным строкам не прерывают весь импорт: они записываются в
отчёт, остальные строки импортируются. Ошибка базы данных откатывает текущую
операцию. Если не сопоставлено обязательное поле «Название», импорт не
начинается.

## CSV: пример

```csv
Название;Артикул;Категория;Цена;Себестоимость;Остаток
Кофе;COF-1;Напитки;150,00;60,00;20
Чай;TEA-1;Напитки;100,00;40,00;15
Доставка;SRV-1;Услуги;300,00;100,00;
```

Для CSV «таблица» — это сам файл, а имя таблицы совпадает с именем файла без
расширения. Остаток можно оставить пустым: тогда склад не корректируется.

## Рекомендации

1. Сначала импортируйте категории, затем товары, затем способы оплаты.
2. Сделайте копию старого файла — хотя он открывается только на чтение,
   это защитит от ошибок.
3. Проверьте несколько строк в preview, особенно цены и остатки.
4. После импорта откройте «Товары и услуги» и «Склад», проверьте остатки.
5. Если что-то пошло не так, закройте приложение и восстановите базу из
   копии `before-import` (см. [база данных](database.md)).
6. Импорт не переносит историю продаж. Старые продажи при необходимости
   ведите отдельно или добавьте их вручную после согласования методики.
7. Состав услуг и признак расходника не импортируются автоматически. После
   импорта отметьте материалы как расходники и назначьте их услугам в карточках
   (см. [руководство администратора](admin.md)).
