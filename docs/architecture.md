# Архитектура

## Общая схема

```text
PySide6 UI
   │  вызывает сервисы, не работает с SQL напрямую
   ▼
AppContext  ── связывает сервисы и пути приложения
   │
   ├── UserService        пользователи, вход, права
   ├── SettingsService    настройки
   ├── CatalogService     категории, товары, услуги, расходники, цены, склад
   ├── PaymentMethodService
   ├── ShiftService       смены и события смен
   ├── SalesService       атомарные продажи
   ├── StatsService       отчёты и статистика
   ├── ReceiptService*    текстовые чеки и отчёты (функции)
   └── LegacyImportService
   ▼
Database  ── SQLite, транзакции, проверка целостности, backup
```

\* Модуль `services/receipts.py` содержит функции, а не класс-сервис.

│   ├── app.py                  старт, восстановление БД, окно входа
│   ├── config.py               пути и константы
│   ├── context.py              AppContext

│   ├── schema.sql              схема БД версии 2
│   ├── models.py               dataclass-модели
│   ├── money.py                форматирование и разбор сумм

## Слои и правила

1. **UI** не выполняет SQL. Страницы вызывают методы сервисов и показывают
   ошибки через общие диалоги.
2. **Сервисы** проверяют входные данные, выполняют операции в транзакциях и
   возвращают модели. Исключения: `ValidationError`, `SaleError`,
   `ShiftError`, `AuthError`, `ImportError_` (все наследуются от
   `ServiceError`).
3. **Database** отвечает только за соединение, транзакции, миграции,
   целостность и резервные копии.
4. Деньги передаются как `int` в копейках. Форматирование — только в UI и
   текстовых отчётах.
5. Все записи, затрагивающие несколько таблиц, выполняются в
   `Database.transaction()`. Вложенные вызовы используют `SAVEPOINT`.
6. Состав услуг (`service_consumables`) меняется в сервисе каталога и
   применяется атомарно вместе с созданием/изменением услуги.

## Запуск приложения

`pos.app.main()`:

1. Определяет `AppPaths` (данные, БД, backups, receipts, логи).
2. Настраивает логирование и `faulthandler`.
3. Создаёт `QApplication`, применяет тему.
4. Берёт эксклюзивную блокировку `data/pos.lock` — второй экземпляр
   приложения не запустится.
5. Открывает базу через `_open_database()`:
   - `Database.connect()` создаёт схему при первом запуске, применяет
     настройки по умолчанию;
   - выполняется `PRAGMA quick_check`;
   - при повреждении предлагается восстановление из последней резервной
     копии; повреждённый файл сохраняется рядом как `pos-corrupt-*.db`.
6. Создаёт `AppContext`, делает резервную копию при запуске (если включено).
7. Показывает окно входа. После успешного входа открывается `MainWindow`.
8. При выходе закрывает базу и снимает блокировку.

Если в базе ещё нет пользователей, окно входа работает в режиме первого
запуска и создаёт администратора.

## Интерфейс

- `ui/login.py` — вход и первичная настройка администратора.
- `ui/main_window.py` — боковая навигация, верхняя панель смены, смена
  пользователя без перезапуска.
- `ui/seller_page.py` — каталог, корзина, предварительный чек, оплата.
- `ui/payment_dialog.py` — разделение суммы между способами оплаты.
- `ui/shift_dialogs.py` — открытие/закрытие смены и печатный отчёт.
- `ui/admin/*` — разделы администрирования.
- `ui/theme.py`, `ui/widgets.py` — оформление и общие элементы.

Навигация фильтруется по правам пользователя. Администратор видит все
разделы; продавцу показываются только разрешённые. Дополнительные права
продавца позволяют открывать отдельные административные разделы, не меняя
роль.

## Зависимости

Единственная runtime-зависимость — `PySide6`. Тесты используют `pytest`.
Управление окружением и запуском — через `uv`.
